Privacy Policy

How this application handles Google user data.

Home Terms of Service

Last updated: 21 August 2026

1. Who this covers

“The application” is a personal video publishing automation operated by a single individual (“the operator”) for their own YouTube channel. It is not offered as a service to the public: there is no sign-up, no user accounts, and no way for a third party to connect an account to it.

The only person who ever authorises the application is the operator, using their own Google Account. Everything below therefore describes how the application handles the operator’s own data.

2. What data the application accesses

The application requests two Google OAuth scopes and uses them for these purposes only:

ScopeWhat it is used for
https://www.googleapis.com/auth/youtube.upload Uploading video files the application has produced to the operator’s channel.
https://www.googleapis.com/auth/youtube.force-ssl Setting the title, description, tags, category, custom thumbnail and scheduled publication time on those uploads.

The application does not access, request or store:

  • viewer, subscriber or audience information;
  • comments, messages or community posts;
  • channel analytics or revenue data;
  • contacts, email, files, calendar, location, or any Google service other than YouTube;
  • any video the application did not itself upload.

3. What is stored, and where

The application stores one item of Google user data: the OAuth refresh token issued when the operator grants consent. It is held as an encrypted secret inside the operator’s own automation environment (GitHub Actions repository secrets) and is used solely to obtain short-lived access tokens for uploading.

The token is never written into source code, logs, video files, or any published output. No copy is kept on any server controlled by anyone other than the operator and the platform hosting the automation.

Alongside it, the application keeps a plain list of the topics it has already published, so it does not repeat itself. That list contains no personal data.

4. What is not done with the data

Google user data obtained through these scopes is never:

  • sold, rented or traded;
  • transferred to advertisers, data brokers, or resellers;
  • used for advertising, profiling, or credit assessment;
  • used to train generalised artificial intelligence or machine learning models;
  • read by a human, except where the operator inspects their own account.

The application’s use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

5. Third-party services

To produce a video, the application sends its own generated material — topic descriptions, narration text and scene descriptions — to third-party providers for script generation, speech synthesis and video rendering. No Google user data is included in these requests. The material sent is content the application wrote itself, not information obtained from any Google API.

6. Retention and deletion

The refresh token is retained only while the automation is in use. It is deleted when the operator removes it from the automation environment, and it is invalidated immediately if access is revoked in the Google Account.

Because the application holds no data belonging to anyone other than the operator, there is no third-party data to export or erase. Should that ever change, this policy will be updated before any such processing begins.

7. Revoking access

Access can be withdrawn at any time at https://myaccount.google.com/permissions by selecting this application and choosing “Remove access”. Uploads stop immediately; videos already published remain on the channel and are managed through YouTube as normal.

8. Security

Credentials are stored as encrypted secrets and are exposed only to the automation run that uses them. All communication with Google APIs uses HTTPS. The OAuth client secret and refresh token are excluded from version control.

9. Children

The application is not directed at children and does not knowingly process the data of anyone under 13. Uploads are marked as not made for kids unless the operator configures otherwise.

10. Changes to this policy

If the application’s data handling changes, this page is updated and the date at the top is revised. Material changes that widen the scopes requested will require fresh consent from the operator.
